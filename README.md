# vityarthi project - java blockchain implementation

hey guys, this is my final evaluated project for the course. instead of just doing a basic data structure assignment, i decided to actually build a fully functional blockchain ledger from scratch in java. i wanted to figure out how things like bitcoin and ethereum actually secure their networks under the hood.

i didn't use any external frameworks or libraries like maven or bouncycastle. all the cryptography, hashing, and networking logic is built using pure core java (`java.security` mostly).

## 🚀 how to run this on your machine

it's super easy to run because it has zero external dependencies. u just need java installed (i used jdk 8 but any recent version is fine).

1. open your terminal, cmd, or powershell.
2. navigate to the folder where you saved these files:
   `cd path/to/VITYARTHI_Blockchain_Project`
3. compile all the java classes at the same time:
   `javac *.java`
4. run the main ledger engine:
   `java LedgerCore`

## 🧠 what does this project actually do?

most tutorials online just show you how to link blocks with strings. i wanted to take it a step further and implement the **four core pillars** of a real cryptocurrency network:

### 1. real digital wallets (rsa cryptography)
early on i just used normal strings to represent users (like "studentA"). but in the real world, anyone could just fake a string. so i built a `Wallet.java` class. 
now, every time a new wallet is created, it generates a real **RSA-1024 public and private keypair**. when you want to send funds, you have to use your private key to digitally sign the transaction. the network then uses your public key to verify that the signature is legit before accepting the transfer.

### 2. the mempool (pending transactions)
in a real blockchain, transactions don't instantly go into a block. they wait in a queue. 
i implemented a mempool (`pendingTransactions` list). when someone sends money, the network verifies the rsa signature and then throws the transaction into the mempool. it sits there until a miner decides to bundle it up.

### 3. proof-of-work mining & system rewards
to get transactions out of the mempool and into a block, a node has to mine it. 
i added a proof-of-work algorithm in `NodeBlock.java`. the miner has to guess a random number (the nonce) over and over again until the block's sha-256 hash starts with a certain number of zeros (the difficulty target). 
once they find the hash, the block is added to the chain, and the miner gets rewarded with 50 coins generated by the system.

### 4. dynamic utxo balance checking
you can't spend money you don't have. but blockchains don't just store a "balance" variable. 
i wrote a method that dynamically calculates a wallet's balance by scanning every single transaction in the entire blockchain history to see how much money came in vs how much went out. it also checks the mempool to make sure you aren't trying to double-spend funds that haven't been mined yet.

## 🛡️ the hack simulation (testing security)

i wanted to prove that blockchains are immutable, so i wrote a live hack simulation into the `LedgerCore.java` main method.

**here is what happens when u run the code:**
1. it generates a few wallets and does some normal transfers (with rsa signatures).
2. miners mine the blocks and everything is validated.
3. then, a line of code acts like a hacker and forcefully breaks into the genesis block, changing a past transaction amount from 300 to 9999.
4. the system periodically runs an integrity check. it recalculates the **merkle root** of every block. 
5. because the transaction data was changed, the new merkle root doesn't match the old one. this completely changes the block's hash, which breaks the chronological link to the next block. 
6. the system instantly catches the error, spits out a warning, and rejects the hacked chain.

it's pretty cool to see it in action in the terminal!
